# AutoVault: Technical Overview

Local-first vehicle-tracking PWA. React + TanStack Start, no backend, all data in the browser's `localStorage`.

## Stack

- [TanStack Start](https://tanstack.com/start): React, file-based routing (TanStack Router), SSR via [Nitro](https://nitro.build)
- TypeScript, strict mode (`exactOptionalPropertyTypes` on, see [Gotchas](#gotchas))
- Tailwind CSS v4
- [Motion](https://motion.dev) for animation
- Sonner for toasts
- Playwright for end-to-end tests

Deployed to Vercel; the Nitro Vite plugin (`vite.config.ts`) is required for that. Without it, Vercel serves the app as a static site with no SSR function and every route 404s.

## Contributing

Contributions are welcome, bug fixes, new features, or just cleanup. Open an issue to discuss what you'd like to change, or send a pull request directly.

A few things that help a PR go smoothly:

- Run `npm run lint` and `npm run test:e2e` before opening it.
- Keep the local-first, no-backend design intact: no new network calls, no account system.
- Match the existing patterns described below, especially the data layer and hydration rules; they're the two most common sources of bugs in this codebase.

## Data layer

There is no database and no API. All state lives in `localStorage`, read into a module-level store (`src/lib/store.ts`) and exposed to components via `useSyncExternalStore`.

**Pattern used everywhere for shared, persisted state** (`use-garage-data.ts`, `use-unit-prefs.ts`, `use-backup-settings.ts`, etc.):

```ts
let state = readFromLocalStorage();
const listeners = new Set<() => void>();

function setState(next) {
  state = next;
  localStorage.setItem(KEY, JSON.stringify(next));
  for (const l of listeners) l();
}

export function useThing() {
  return useSyncExternalStore(
    (listener) => {
      listeners.add(listener);
      return () => listeners.delete(listener);
    },
    () => state,
    () => seedState, // server snapshot, see Hydration below
  );
}
```

Don't reach for plain `useState` + `useEffect` for anything shared across components; it doesn't propagate updates between instances and reintroduces the hydration bug below.

## Hydration

This is an SSR app; the first render must match on server and client. Two rules follow directly from that:

1. Never call a browser-only API (`window`, `navigator`, `matchMedia`) synchronously in a component body. Do it inside `useEffect`, backed by a `useState` that starts at the server-safe default.
2. Every `useSyncExternalStore`-based hook must provide a real `getServerSnapshot` (usually the seed/empty state), not `undefined` or the same accessor as the client snapshot.

Violating either produces a React error #418 hydration mismatch, and it's the failure mode that keeps recurring, so grep for `typeof window` / `typeof navigator` before adding new client-only reads.

## Routing

File-based via TanStack Router ([naming conventions](https://tanstack.com/router/latest/docs/framework/react/routing/file-naming-conventions)). A trailing underscore on a segment (`vehicle_.$vehicleId.edit.tsx`) opts out of implicit route nesting. `routeTree.gen.ts` is generated by the Vite plugin on `dev`/`build`; never edit it, and if TypeScript complains a new route doesn't exist yet, run a build once to regenerate it.

Tabs on the vehicle page are deep-linkable through a search param (`/vehicle/$vehicleId?tab=glovebox`), which is how the document pages link back to the right tab.

## Add forms

Adding an expense or a document is data-driven, so a new category or type is a config change, not new JSX.

- **Expenses** (`/add/expense`): `src/lib/expense-fields.ts` lists the extra fields per category. Their values are stored in the entry's `note` as `Label: value` parts and parsed back when editing. **Service** is just a category: it adds the work picker, invoice and next-service fields and saves as a `service` timeline entry, and servicing something on the vehicle's checklist resets that item (`checklistItemsServiced` in `src/lib/analytics.ts`). Fuel has its own page.
- **Documents** (`/glovebox/new` and its edit page): `src/lib/document-fields.ts` relabels the shared fields per type and adds extras, which are saved in the document's optional `details` map. `DocumentForm` renders both the add and edit pages.
- **Shared pieces:** `FieldSpec` (`src/lib/form-fields.ts`) describes a field, `FieldRows` renders a list of them, `TilePicker` is the icon-tile selector, and `InlineChips` is the one-line pill selector.

## Icons and appearance

- **Icons:** `src/lib/icons.ts` assigns one icon per concept (`appIcons.fuel`, `appIcons.service`, …). Use it instead of importing a different lucide icon for the same thing, and add new concepts there.
- **Theme and accent:** `src/hooks/use-theme.ts` stores the light/dark choice and an accent colour (`blue`, `teal`, `graphite`, or a custom hex). The accent works by overriding the `--primary`/`--ring` tokens, through `data-accent` rules in `src/styles.css` or inline properties for a custom colour. Anything coloured with `var(--primary)` follows it automatically.

## Backup format

`.autovault` files are JSON (`{ vehicles, timeline, docs?, notes?, checklist? }`), optionally wrapped in an AES-GCM envelope (`src/lib/crypto.ts`, PBKDF2-derived key from a user passphrase). Restoring supports two modes (`src/lib/store.ts`'s `restore(data, mode)`):

- `replace`: overwrites local data entirely.
- `merge`: merges by `id`, incoming entries win on conflict.

## Notifications

Real OS notifications, not just in-app toasts: `src/hooks/use-reminder-notifications.ts` runs once per app load, checks service/document/checklist due-status, and calls `registration.showNotification()` on the service worker (`public/sw.js`) if the user has granted permission via the Settings toggle. A cooldown log in `localStorage` prevents re-notifying for the same item within a few days.

## Updates (installed PWA)

An installed PWA (especially on iOS) has no hard reload, so **Settings → App → Check for updates** does it. It only appears when the app is running standalone.

- `vite.config.ts` stamps each build with an id (`VERCEL_GIT_COMMIT_SHA` on Vercel, else the git short SHA, else the build time). It is baked in as `__BUILD_ID__` and published as `/version.json`.
- `src/hooks/use-app-update.ts` fetches `/version.json` (bypassing every cache) and compares it with `__BUILD_ID__`. Same id: "No updates yet". Different: it clears the service worker's caches, asks it to update, and reloads. Unreachable: it says so.
- **Data is untouched.** Only the service worker and its caches are cleared; everything lives in `localStorage`. Navigations are network-first, so the reload picks up the new HTML and its new hashed assets.
- `public/sw.js` must never cache `/version.json`; it returns early for that path. Bump `CACHE_NAME` there if you ever need to force every installed copy to drop its caches.
- The service worker file itself only changes when its own bytes do, so the browser's built-in SW update check can't see an app-only deploy. That's why the build id exists.

## Installed-app mode

When the app runs standalone (home-screen PWA), `src/hooks/use-standalone-lock.ts` adds `html.standalone`, tightens the viewport meta to `user-scalable=no`, and blocks iOS pinch gestures; `styles.css` then pins the page to the device width and disables overscroll and sideways panning. Normal browser tabs are untouched, so zoom stays available there for accessibility. The app shell uses `min-h-dvh` so it matches the visible screen height on mobile.

## Currency

No live exchange rates; the app makes no network calls by design. `src/lib/units.ts` stores fixed conversion rates from INR (the canonical storage currency) and converts for display only; money is always entered and persisted in INR regardless of display currency.

## Testing

`e2e/smoke.spec.ts` covers onboarding → add vehicle, edit/delete, adding a fuel entry, an expense with category fields, a service record with a custom work item, an insurance document, search, a settings toggle round-trip, the installed-PWA update check (up to date, new build with data kept, offline), and backup export. The first run needs a browser: `npx playwright install chromium`. `playwright.config.ts` builds and serves the app before running. Run with `npm run test:e2e`.

## Gotchas

- **Don't seed `useState` from store data.** On a direct page load the store is still empty on the first render, so a default like `useState(String(vehicle?.odometer ?? 0))` is stuck at `0`. Keep `""` for "untouched" and fall back to the live value at render time (see `add.odometer.tsx`).
- **`exactOptionalPropertyTypes`**: a prop typed `foo?: T` does not accept `foo={cond ? value : undefined}`. Use a conditional spread instead: `{...(cond && { foo: value })}`.
- **Vercel 404s on every route**: almost always means the `nitro()` plugin is missing from `vite.config.ts`, or a stale `.output/` from before it was added.
